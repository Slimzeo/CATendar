# Electron → Wails 迁移评估

## 当前项目体量

| 部分 | 代码量 | 复杂度 |
|------|--------|--------|
| Vue 3 前端（组件 + stores + api）| ~500-700 行 | 低 |
| Electron 主进程（main.js + preload.js）| ~210 行 | 中 |
| Go Echo 后端 | ~410 行 | 低 |

---

## 迁移工作量评估：**中等**

合理估计：**1-2 周**可完成核心迁移。

---

## 需要改的部分

### 1. Frontend（工作量：低）

- **`api.ts`**：把 axios HTTP 调用改成 Wails bindings 调用（`window.go.backend.Event.GetAll()` 等）
- Vue 组件、Pinia stores、Naive UI：**全部不用改**
- Vite 配置：端口可能调整，其他不变

### 2. Electron → Wails 主进程（工作量：中）

当前 Electron 做的事，Wails 全都有内置 API：

| 当前 Electron 功能 | Wails 等效 |
|-------------------|-----------|
| `child_process.spawn` Go 进程 | Wails 自动管理，0 代码 |
| `net.Socket` 端口轮询 | Wails 内置 readiness，无需此逻辑 |
| `BrowserWindow` 窗口管理 | `runtime.Window` |
| `Tray` + `Menu` | `runtime.Tray` |
| `setAlwaysOnTop` | `window.SetAlwaysOnTop()` |
| `open-external` | `runtime.BrowserOpenURL()` |
| `app.setLoginItemSettings` | `app.SetLoginItemSettings()` |

### 3. Go Echo → Wails Go（工作量：中）

当前 Echo REST API：
```
GET    /api/health
GET    /api/events?start=&end=
GET    /api/events/:id
POST   /api/events
PUT    /api/events/:id
DELETE /api/events/:id
```

**方案 A（推荐，最小改动）**：保持 REST API 风格
- Go 后端继续用 `net/http` 或轻量框架注册路由
- 前端通过 Vite 代理或直接调用 `http://localhost:PORT/api/...`
- Go 代码 95% 不变
- **预计 3-5 天完成**

**方案 B**：Wails IPC Bindings（更 Wails 风格）
- Go 函数用 `//go:build wails` 注解暴露
- 前端通过 `window.go.backend.Module.Function()` 调用
- 需要重写所有 API 调用
- **预计 1-2 周完成**

### 4. 数据库 SQLite

**不用改**，`github.com/mattn/go-sqlite3` 或 `modernc.org/sqlite` 在 Wails 中完全兼容。

### 5. 打包构建

- `package.json` 的 `electron:dev` / `electron:build` 替换为 `wails dev` / `wails build`
- `electron-builder` 配置替换为 `wails.json`
- `electron-builder` 和 `concurrently` 等依赖可以删除

---

## 迁移后的架构对比

### 现在（Electron + Go spawn）
```
用户运行: npm run electron:dev（两个终端）
           ├─ Vite (port 5179)
           └─ Electron
                └─ spawn Go 进程 (port 18082)
                    └─ SQLite
```

### 迁移后（Wails）
```
用户运行: wails dev（一个命令）
           └─ Wails 自动管理
               ├─ Go 后端（同一个进程内，无端口）
               ├─ Vite dev server
               └─ 原生窗口
```

打包后：**一个 .exe 文件**，双击即开，无需安装 Runtime。

---

## 风险点

1. **Naive UI + Wails**：理论上兼容，但需实际测试
2. **`setAlwaysOnTop`** 在多窗口场景行为可能与 Electron 略有不同
3. Wails 对 Go 版本有要求（通常需要 Go 1.18+）
4. 如果选择方案 A，dev 模式下仍有 Vite proxy 依赖

---

## 下一步建议

1. 先在 `fronted-wails` 目录初始化一个最小 Wails + Vue 3 项目，验证核心功能跑通
2. 然后逐步迁移：先跑通窗口/Tray，再迁移 API，最后接数据库
3. 建议选择方案 A（保持 REST API），最小化改动
